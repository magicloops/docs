# Authorization Token Documentation

## **Definition**  
An **authorization token** is a security credential used to verify a user's identity and grant access to specific resources, APIs, or services. It acts as a **digital key**, proving that the requester has the necessary permissions to interact with a system securely.

---

## **Key Characteristics**  

1. **Unique & Secure**  
   - Each token is **unique** and often time-sensitive, reducing the risk of unauthorized access.  
   - Tokens should be stored securely and not shared publicly.

2. **Bearer Authentication**  
   - Most APIs use **"Bearer Tokens"**, passed in the HTTP Authorization header.  
   - This allows for **stateless authentication**, meaning the server does not need to store session data.

3. **Token Expiration**  
   - Tokens may have an **expiration time** and require renewal.  
   - This prevents misuse in case of unauthorized access.

4. **Common Formats**  
   - **JSON Web Token (JWT):** Encoded payload containing user information and claims.  
   - **Opaque Tokens:** Random string-based keys where data is stored on the server.

5. **Issued by Authentication Services**  
   - Tokens are typically generated by **authentication providers** such as:  
     - **OAuth 2.0**  
     - **OpenID Connect**  
     - **API Key-based Systems**  

---

## **Example Usage**  

A request using an authorization token in an API call:

```http
GET https://api.example.com/user/data
Authorization: Bearer YOUR_AUTH_TOKEN
```

**Example Response (JSON):**
```json
{
  "id": 123,
  "username": "johndoe",
  "email": "johndoe@example.com",
  "roles": ["user", "admin"]
}
```

---

## **Types of Authorization Tokens**  

🔹 **Access Token**  
   - Used to authenticate and access protected resources.  
   - Short-lived and requires renewal.  

🔹 **Refresh Token**  
   - Allows obtaining a new access token **without requiring** user credentials again.  
   - Typically long-lived but must be stored securely.  

🔹 **ID Token**  
   - Used in **OpenID Connect (OIDC)** to provide identity information about a user.  
   - Often returned along with an access token.  

---

## **Best Practices for Handling Tokens**  

✅ **Use HTTPS** → Always transmit tokens over secure connections.  
✅ **Implement Token Expiration** → Reduce risks by setting expiration times.  
✅ **Store Securely** → Never expose tokens in URLs, logs, or frontend applications.  
✅ **Use Refresh Tokens Properly** → Limit how often a user must reauthenticate.  
✅ **Revoke Compromised Tokens** → Allow servers to invalidate tokens when needed.
